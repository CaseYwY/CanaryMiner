# Default-off readonly billing candidates (P-05r)

M-TARIFF/M-ENERGY; R-TAR-002–005, R-ENG-001, R-SAFE-001/002, R-PRIV-002 and R-REL-001; T-TARIFF/T-ENERGY/T-INTENT/T-PRIVACY; D-57. `BillingComputeOwner` turns a source notification into one bounded readonly energy query and an exact hypothetical next monetary prefix. It has **no monetary writer, staged-input client, importer, collector or mining controller**. Linking it does not activate it.

## Frozen context and observations

The caller supplies one installed trace-helper path and the exact immutable `BillingOwnerBinding` shared by an approved billing owner. Policy is disabled by default. `start(generation)` is single-use and starts no source query. The caller then delivers the same-generation billing owner's immutable snapshots through memory-only `observe`.

Only a Ready, reviewable, stable stage/current-money observation with a settled journal, no temporary/partial/Issued stage, no unknown intent, a source-bound unsettled monetary prefix and available ledger capacity can admit computation. Context identity cannot change within the instance. Observed owner revisions must advance; stale copies and a pre-invalidation revision cannot restore authority. A newer observation cancels in-flight work and makes any retained candidate historical. Stopped/clock-faulted/faulted billing observations revoke the compute owner too.

`BillingSourceNotice` carries a source checkpoint identity, observed instant and through-bound. It is a **scheduling hint**, not committed-source proof, complete coverage or a monetary checkpoint. An identical notification is deduplicated; busy admission does not queue a backlog. `refresh` is an explicit readonly retry of the last admitted notice, not a replay of any financial write. No periodic source polling or automatic retry occurs. Rejected admission does not replace the last accepted hint.

## One query, exact candidate

Each accepted job freezes the billing review and current UTC query time. The query begins at that exact monetary prefix's `opening.throughUtcMs`, ends at the lesser of the notified through-bound and explicit cycle end, and anchors source ancestry at the committed monetary source checkpoint. It never extends power after the final observed sample. The existing parent-bound [trace helper](energy-trace-helper.md) reopens/audits the source journal and ledger read-only; its actual checkpoint, coverage, ancestry and complete trace supply the evidence. A hint cannot supply missing intervals or overwrite these facts.

After the validated reply, `makeBillingSourceChunk` preserves the full canonical source receipt with its original query/observation times and normalized source request identifiers. `accrueBill` computes a hypothetical exact next prefix from the frozen tariff/opening and full trace. The candidate stores this preview, immutable original, reviewed monetary snapshot and separate notification. It never changes the committed prefix, creates `.billing-input`, or posts income. Partial/absent coverage, source conflict/detail expiry, trace capacity, calculation failures and unavailable transport publish no reviewable candidate; earlier candidates can remain only as labelled historical data.

This slice admits the existing **SyntheticFixture** billing qualification only. Arithmetic is restricted to explicit UTC/fixed clocks so the background compute step cannot lazily load named-zone data. Named private TZDB/loader/runtime qualification remains separate. Rate/origin/basis rules, all-units accumulated repricing and end-cycle minimum settlement retain their existing exact arithmetic semantics.

## Bounded lifetime and submission boundary

There is one queued/in-flight job, no backlog, one helper flight and a 500–60,000-ms shared operation deadline. The trace cap is independently selectable from 1 through 512 intervals; existing source/request/reply, receipt and monetary limits remain unchanged. Admission copies only a bounded hint and immutable shared pointers. Filesystem/SQLite work stays in the helper. Cancellation and the deadline are checked around bounded background validation/arithmetic; this is not a hard real-time CPU/allocation/OS guarantee.

UTC/monotonic reversal or more than two seconds of cumulative elapsed disagreement latches ClockFault. Actual queried source checkpoints and observed monetary heads cannot go backward or fork at the same sequence. Notification identifiers are not used as authoritative high-water proofs. Unreaped takes precedence over an invalidated flight and permanently closes admission. `requestStop` revokes without join or I/O; `stop` joins outside stop/render paths. Late successful results cannot alter the frozen terminal snapshot. A fresh instance is required after stop/fault, and it still does not automatically read or replay anything.

A candidate's `reviewable` flag means eligible for review against the **last delivered monetary snapshot**, not an atomic lock on the current live ledger. The caller must propagate owner changes. An eventual explicit Submit must pass the candidate's original and its frozen monetary generation/revision to `BillingOwner::submitReviewed`; that owner performs its full bracket/preflight and live helper CAS. Tests submit through this separate path and confirm that an intervening monetary refresh rejects the old reviewed revision. No candidate can authorize itself to write.

Invented notification heads cannot poison the proven high-water mark. Separate compilation injects Unreaped without placing a seam in ordinary artifacts; an independent owned parent verifies helper death and unchanged stores.

Executed evidence: Windows/MSVC focused CTest **3/3**; Windows and Linux/WSL/direct GCC compute/latch/lifecycle **144/14/7**. The same Linux selection passes **ASan+UBSan**, reusing unchanged already-instrumented dependencies. The initial 115-check fixture run failed three assertions: all-missing power had been mislabelled Partial, and deleting a source main file left SQLite companions that correctly blocked CreateNew. The fixtures now use genuinely partial coverage and restore a proven Empty source pair before constructing a same-sequence branch; production preservation rules were unchanged. Final review added actual monetary rollback/fork reconstruction, exact context identity and hint-only high-water checks.
