**Cooperative software admission, not a qualified physical collector or completed application-wide lifecycle.** This
slice carries [P-14d's original scopes](native-process-scopes.md) through the history owner, authorization owner,
bounded producer, held collector and outer development energy runtime. Billing, forecast, market, detection/safety and

source qualification, storage formats and production activation are unchanged.

## Observed failures and controls

The actual parent/owned-thread/native boundary fixture first has **fourteen failing scenarios out of sixteen**:

- History/authorization jobs held before their first native call launch after an already-settled foreign fault.
- Ready snapshots still offer current authority/accept jobs; a higher history generation can borrow the new epoch.
- The held collector/producer still report Held/Collecting and accept readings; the outer runtime can start its deferred
  authorization owner in the new epoch. Stale caller scopes can also start new owners.

Unchanged-epoch history restart and existing exact authorization uncertainty retention are passing controls. The separate
cross-platform five-layer scope program fails **five of fifteen** checks against the original support archive, with all
fresh explicit controls passing. Its helper deliberately does not exist, so it cannot execute a child or touch a store.

Expanded allocation tests make **twenty of twenty-two** scenarios fail against that same original archive, including two
uncaught `bad_alloc` aborts after old input admission instead of revocation. These are test-only allocation failures, not
physical exhaustion or native-kernel proof. A further runtime stop-then-fault case fails **two of eleven** checks during
implementation; preserving already explicit Stopped state fixes it without erasing native-fault transport status.

The retained native fixture dispatches its fixed helper flag before parent construction, rejects unknown modes and has a
separate two-case non-recursion guard. Strict synthetic replies bind requests but never open the supplied path or execute
storage/collector functions. Its held child adopts the owning parent and has a finite fallback lifetime. Cleanup targets
only actual owned native processes. No GPU, driver sampling, real game/account/wallet/utility plan/pool, public network or
OS trust-store operation is involved.

## One original lifetime at every layer

1. History and authorization bind once before their threads; each thread explicitly installs the same original scope.
   Queue admission, pre-pop execution, final publication, review acknowledgement, plan transfer and snapshots check it.
2. Producer/held collector bind before inner starts. Action/tick/snapshot boundaries revoke cached Collecting/Held
   authority, discard unsent readings and signal inner cancellation without joining.
3. The outer runtime binds before its capture decision. Delayed authorization and nested actions use that original scope.
   A fault revokes **both** inner owners before fallible projections. Already explicit Stopped state remains Stopped;
   native-fault Unreaped transport remains separate.

No implicit thread propagation, mining token, automatic replay/restart or native OS atomic transaction is added. A stale
caller is refused or gets an unavailable view, not permission to cancel a different healthy facade. The owner latches
only when its own bound global lifetime becomes invalid. Normal increasing-generation history stop/start remains possible
in the **same** valid native epoch; other layers remain one-attempt. A different explicit owner must follow durable
inspection/review after a native fault; constructing a replacement is not recovery permission.

## Unknown issuance and immutable history

- Queued unissued work is discarded, not called committed or rolled back. Potentially issued batches, CreateNew,
  authorization mutations and Provision retain original input/unknown outcome without replacing older uncertainty.
- A definite returning result clears only matching speculative uncertainty, never current-authority revocation. Separate
  native no-child refusals verify that creation/mutation/Provision acquire no fabricated unknown flags or originals.
  Created/unacknowledged Provision keeps its complete original selected-set request across stop.
- Successful old replies remain immutable **historical** facts, not fresh readings, permission or resets. Cancellation and
  destruction never substitute for durable reconciliation or actual exit proof.

Memory/cancellation changes precede shared snapshot allocation. Preallocated unavailable views mask old Ready/Collecting/
Held views if every calling-thread allocation fails. Five allocation variants exercise that fallback and rejected actions;
shipping code contains no allocator/native/thread hooks. Projection failure does not delete retained originals; explicit
stop/join can publish them later. Idle cancellation remains cooperative, not a hard process-exit deadline.
