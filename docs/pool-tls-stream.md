# Retained native TLS helper (P-12f)

This is the P-12f baseline record. Ordinary integration and installation were added in P-12h/i; [P-12j](pool-tls-fallback.md) versions the private protocol to C2/R2 and adds a separately authorized, explicitly identified plaintext mode. The historical absence of ordinary activation below does not describe those later modules.

M-TLS; R-TLS-003/004; T-TLS/T-INTENT/T-PRIVACY/T-RELEASE; D-97.

**Default-off development capability, not ordinary mining activation.** An explicit injected `PoolTlsProcessTransport` starts one owned native duplex helper, which performs DNS/connect/TLS and retains that exact authenticated socket/context for application records. It never treats the [one-shot check](pool-tls-check.md) as authentication for a second connection. No ordinary miner factory, SSL URL, preset, settings, plaintext fallback, donation permission, helper installation or production binary is added.

## Lifetime and transport

`CANARY_ENABLE_POOL_TLS_STREAM=ON` requires the independently selected connection capability; all native TLS/connection/stream and loopback-test options default OFF. Windows uses Schannel and Linux uses OpenSSL. The helper alone owns resolver calls, sockets, credentials, native TLS and destruction. A retained shared platform owner outlives the stream/socket, including Windows Winsock cleanup. Normal automatic Windows validation remains distinct from explicit development private trust; no normal-trust positive is inferred from private loopback success.

The parent launches a fixed explicit helper without a shell, application credential arguments or inherited proxy/keylog/private environment. Paired nonblocking private pipes (Windows) or a nonblocking local socketpair (Linux) carry at most one command flight. Each parent poll performs at most one 4096-byte read/write and a zero-wait exit observation; a partial queued write cannot be replaced. Windows binds inherited handles to the parent and owns a kill-on-close single-process job. Linux uses an owned process group, peer-credential/parent checks and parent-death signal. True owned-parent termination and backpressured pipes are tested; they are not forced native OS or unkillable-kernel experiments.

At most 64 process reservations exist in this module. Before launch, storage for all quarantine slots is allocated. Unresolved wait/reaping ownership blocks new module admissions, and destruction retains that exact owner rather than dropping its handles/PID or inferring exit. This is **module-local quarantine**, not a claim that every application helper shares one global admission registry or that an actual unreapable kernel task has been qualified. Concurrent calls on one process/transport are unsupported; one owner thread serializes them.

## Private RPC and evidence

Strict length-prefixed `CMTLSC1`/`CMTLSR1` frames retain incomplete tails. Sequence starts at one with Open, advances consecutively and never wraps/reopens. Parse failure, unexpected/stale/duplicate reply, cancellation, clock reversal, original flight deadline and failed helper ownership latch terminally. Original Open issuance precedes process startup; the helper clips its native budget to the remaining original deadline. A command lasts at most 60 seconds; ordinary parent RPC flights use five seconds, remote waits at most 25 ms and application chunks at most 16 KiB.

Write copies and native caller storage stay stable across retries. Positive application consumption means the owned ciphertext was completely flushed locally, **not** peer receipt or share acceptance. If a helper disappears after an attempted write with zero confirmed plaintext, the actual canonical source publishes PossiblySent/Unknown and never replays it. Its legacy submitted/unknown counters only cover fully sent requests; they must not be incremented to fabricate a completely sent request from an ambiguous partial attempt. Replies still require canonical request-ID correlation.

An outstanding local IPC read is not buffered TLS/application data. The separate `localReadPending`/`waitLocalRead` barrier resolves the exact pre-submit quiet/read result under the source operation's original deadline, with at most sixteen receive turns and 25-ms waits. Async replacement work retires the old proof before any wire ID/write; failures, unresolved input and partial lines cannot become quiet permission. Existing-job and readonly drains use bounded nonblocking turns, retaining framing instead of waiting twenty seconds for a JSON line promised only by a TLS-control hint. Ordinary TCP behavior stays unchanged.

## Native control regression

A real Windows TLS 1.3 canonical-source loopback first stalled during authorization. A conservative `bufferedRead` workaround hid a malformed Schannel control-token handoff: `DecryptMessage` can leave a five-byte STREAM_HEADER first, with the actual unconsumed token in EXTRA. Relabeling that header alone as TOKEN manufactured an incomplete-message wait, even though the complete peer records were already present.

The corrected handoff validates/preserves the returned EXTRA tail or actual modified DATA/TOKEN, including empty control input; it does not require EXTRA to exist or pass a header/trailer alone as a whole token. Verification/final-output rules remain unchanged. `readProgressReady` now distinguishes an immediate internal retry/control completion from the conservative buffered hint. A genuinely incomplete encrypted record waits for network bytes rather than producing endless READY; the test delivers its tail and verifies exact recovery. [Microsoft's DecryptMessage contract](https://learn.microsoft.com/en-us/windows/win32/secauthn/decryptmessage--schannel) was rechecked for the modified-token handoff. No-extra/key-update/post-handshake-client-auth variants still need their own real-peer qualification.

## Validation and limits

The CPU RPC suite checks framing, strict fields, complete 16-KiB payloads, sequence/deadline/clock/stop/stale reply refusal and stable write retry. Owned-process fixtures exercise exact binary echo, bounded backpressure, multi-poll post-exit tails, cancellation, true parent death and minimized environment. Actual canonical-source regressions cover local quiet/replacement/partial/error/deadline/call-cap and attempted-write Unknown without changing counters' meaning.

Explicit native localhost-only peers exercise binary echo, canonical authorize/notify/submit/correlated reply over TLS 1.3 and TLS 1.2, normal untrusted refusal before application bytes and truncated closure without a submit. All proofs/identities are synthetic; no GPU work, real account, public endpoint, donation route or valid Pearl proof acceptance is implied. Fresh ephemeral test keys remain captured in private scratch, are never logged/committed, and temporary key files are unlinked immediately after server loading. Python is test tooling, not a miner runtime.

Final platform counts, repetitions, sanitizer and artifact/privacy results belong to the [execution ledger](architecture/execution-plan.md). Linux direct GCC is not Linux CMake qualification; native external libraries are uninstrumented. Normal automatic Windows trust positives, IP identity, received private intermediate admission, session cache/auxiliary egress, forced OS API stalls/hard exit bounds, application-wide quarantine, secure config/fallback/donation, deployment and public-pool/GPU/game/production qualification remain open.
