# Lifetime game-to-worker supervision (P-11g)

M-GAME/M-SUPERVISOR; R-GAME-004/005/006 and R-SAFE-001/002; T-GAME/T-INTENT; D-68. `GameWorkerSession` connects one fixed [game runtime](game-runtime.md), one private parent identity, the [command issuer](worker-control.md) and [background native worker owners](worker-process.md). `Supervisor` accepts this through a default-empty `WorkerFleetFactory`; ordinary native startup does not populate the factory or its safety-evidence source.

## One explicit parent lifetime

The session borrows the supervisor's existing intent/token. It never calls `explicitStart`. Start is single-use and validates policy, clocks and slot count before starting its fixed detector and a single background entropy request. That request provisions one parent key plus a frozen budget of at most 256 distinct incarnation keys. Exhaustion latches refusal; there is no automatic entropy refill, replacement helper or new parent session. Keys remain in private memory/control streams.

Each explicitly requested slot freezes its executable, arguments and drain duration. Initial launch and every admitted replacement consume a new key and increasing slot generation. All incarnations share the original parent key/token and the same by-value `GameRuntime`; settings review and worker retries cannot retarget it or clear its episode/profit state. Retired owners/issuers remain retained until final joining. A retry does not rebuild the detector or game guard. A cancelled queued incarnation has no reaping proof; it cannot borrow its predecessor's exit observation.

Only a known reaped runtime-error exit **1**, with settled command bookkeeping before disconnection/exit, is eligible for the supervisor's existing ten-second/three-per-hour retry budget. Clean exit **0**, forced exit **7**, fault **8**, incomplete control evidence and unproven reaping are terminal for that slot. EOF revokes control immediately but is distinct from actual exit. An incomplete/malformed receipt stream remains a control fault even if the same poll observes process exit. Expected operator channel closure does not itself create a malformed-peer diagnosis.

Identity, detector or worker Unreaped blocks the whole session. Current ownership is read after stop/join too, including cancelled/refused startup; a late unresolved result cannot be hidden by an earlier stopped snapshot or operator quit. The registry is still limited to the existing subsystem ownership boundaries, not a newly certified cross-helper kernel quarantine.

## Evidence-derived Run deadlines

The frozen evidence source supplies an explicit aggregate safety observation covering all selected workers, bound to the current epoch, revision and original UTC/monotonic observation times. Missing/foreign/future/stale observations hold the workers. Same-revision substitution or timestamp rollback latches a fault. Cached observations are never restamped by display, receipt, renewal or tick time. The source is a trusted, memory-only integration contract; ordinary NVML fields are not silently promoted into qualified critical-safety evidence.

`GameRuntime::runDeadline` restricts an upper deadline using the **exact detection consumed by its immediately preceding tick**, not a newer independently reread snapshot. Both UTC and monotonic age limit the remaining validity. Off still requires the session's independent valid safety evidence. Normal eligibility is bounded by detection freshness; future qualified coexistence would additionally be bounded by the first ten-minute check boundary or accepted profit-window freshness. Native process episodes still cannot acquire synthetic coexistence qualification.

[P-11k](evidence-deadlines.md) corrects decreasing-skew reuse: detection, accepted profit and safety each retain an original-observation earliest ceiling. Repeated ticks and renumbered cached originals cannot extend it or revive expired evidence. Only a genuinely newer validated observation can bind a new deadline; an accepted new game episode has a separate profit sequence.

Every Run deadline is the minimum of the configured command horizon, remaining safety validity and the game/runtime evidence deadline. The protocol's 5000-ms ceiling is never a replacement for source freshness. A small bounded scheduling margin requests Pause before remaining evidence becomes too short to transport usefully; it does not extend evidence or promise physical pause latency. Each issuer permits one outstanding command. A pending Run must settle before the next Pause can be issued. [P-03i/P-11n](pending-run-revocation.md) revokes the owned channels immediately when that pending Run loses full current-deadline coverage, rather than waiting for receipt or lease expiry. This check uses the actual permission ceiling, not the early-Pause scheduling request; headroom alone cannot revoke a still-covered pending command. Initial startup always requires a real drained Pause.

Pause requests, current drained Paused receipts, Run permission and actual work remain different facts. A new command removes the prior pause proof. Missing profit is not zero profit; the existing ten-minute lock and fresh-only exit rules remain in the same guard. Economic optimization, real reward/price calibration and experience-qualified coexistence are not activated by this bridge.

[P-10j](native-economic-session.md) optionally adds one frozen economic plan/policy per slot, a parent-retained evaluator/budget and incarnation-specific decision-bound command owner. That path takes over issuance after actual initial Pause, delivers through the native owner and admits replacement only after real eligible reaping and exact retirement. Empty economic configuration preserves this original game-only path. Ordinary CLI/source/experience qualification remains separate.

## Supervisor boundary

The supervisor creates the optional fleet once, before starting workers. A refused factory/start never falls back to an uncontrolled worker. The controlled path requests native workers asynchronously, drains bounded complete lines through the existing redactor and uses admitted actual exit results for retries. It shows Pausing versus proven Paused and stops rate-time accumulation while held. The child donation scheduler and shared-loop pause accounting remain authoritative.

Stop revokes the parent intent and fleet before draining or joining. A stop arriving during the evidence callback prevents the following tick/Run; a source exception faults the controlled session. A reaped runtime error racing intentional stop remains a stop with its actual exit code, without a retry or a fabricated protocol fault. Hardware-tuning hooks conflict with this path. All controller methods belong to the same supervisor thread; the entropy, detector and native process owners own their background operations. No private identity, episode or receipt is added to public stats.

[P-11h](game-settings.md) supplies independent native mode/target/scope/timing review and saving; ordinary startup refuses non-Off requests before discovery. An independently qualified critical-safety provider, ordinary CLI factory binding and deployment remain follow-ups. [P-03f/P-11l](supervisor-sampling.md) moves display HTTP/NVML calls off the control thread and retains generation-bound original observations. Synchronous settings saves and console/storage work still need further isolation and physical qualification; a permanently stalled native sampler can still delay the parent's post-drain join. The CPU supervisor fixture retains its explicit five-second synthetic evidence window; shorter freshness/expiry behavior is tested directly at the real controller/transport seam. Linux pre-adoption loader stalls and genuine kernel/driver/disk waits remain unqualified.

## Verification scope

Tests use the actual session, helper-side random identities, native paired channels and CPU child processes. They exercise initial hold, fresh Run, cooling and missing/stale-source Pause, frozen-source deadline bounds, expiry/non-revival, same-revision substitution, old-token stop, process-identity-bound game pause, incomplete detection, unsupported coexistence, fresh debounced exit, repeated worker incarnations retaining an episode, frozen launch arguments and identity-budget exhaustion.

The actual supervisor fixture checks a clean controlled stop and a real runtime-error/reaped replacement after the unchanged ten-second delay, with one fleet factory and increasing worker generation. Memory-only boundary probes separately cover stop before factory/start, no uncontrolled fallback, stop during evidence acquisition, source exceptions and late Unreaped winning over quit. These probes do not claim genuine kernel Unreaped reproduction. Final executed counts and cross-platform/sanitizer evidence are recorded in the execution plan.

The initial regression reproduced an incomplete receipt being masked by simultaneous child exit; the native poll now retains that fault independently of exit status. Further red/green cases caught predecessor reaping proof leaking into a cancelled queued generation and late Unreaped being hidden by cancelled startup. Both are fixed.

The Windows restart fixture originally made every generation exit after 150 ms of Run while expecting the second to stop cleanly. Raw owner/child traces confirmed exit 1 without a protocol fault; the fixture now fails only its first generation and waits for stop in its replacement. Its watchdog includes the unchanged ten-second backoff and refused stats-connect latency. Command/source deadlines are not extended by those waits. An initial Linux LeakSanitizer run exposed external driver allocations from the synthetic UUID; CPU supervisor fixtures now use a test-only unavailable-NVML loader adapter on both platforms. Leak detection remains enabled, with no suppression. Integrated GPU/game acceptance remains scheduled after implementation across the planned modules.

Final Windows/MSVC focused CTest passes **11/11**. Windows/Linux session tests pass **120** checks each; native IPC/identity/owner **122**, runtime **67**, and old supervisor **275/261** also pass. Lifecycle checks verify adopted-parent death before lease expiry and **9** native CLI refusals. Windows protocol **359** and pause/shared-loop **31/57** regressions pass. Linux new-source/test **ASan+UBSan with leak detection** passes session **120**, owner **122** and lifecycle checks, using unchanged instrumented dependencies/child fixtures. Architecture **4/4**, auxiliary-import and native-build-recipe guards pass. The Linux legacy-regression wrapper initially omitted the entropy object at link time; its remaining runtime/supervisor checks were resumed with the corrected list. These are direct-GCC Linux checks, not a Linux CMake or production CUDA/SASS qualification.
