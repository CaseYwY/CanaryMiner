# Game field and human scope labels (P-13v)

M-I18N/M-UI; R-I18N-001/002; T-I18N/T-UI/T-CONFIG/T-PRIVACY; D-120.

**English-only native source extraction and independent typed drafts.** Nine stable `game.field.*` / `game.value.*` keys
in sixteen packs (144 texts) cover the six ordered Mode/Target/Scope/Poll/Exit-debounce/Maximum-age labels, invalid-label
recovery and the two human Windows-session/Linux-native-UID scope descriptions. Literal `ms`, `Windows`, `Linux` and `UID`
tokens stay explicit. All non-English entries remain machine-assisted drafts, not reviewed translations or effective UI.

Native Game settings uses English-only helpers for these labels, retaining exact previous frame bytes, field order,
contextual editing, review/scroll/save/discard, immutable current session and stop behavior. The adapter-value display branch
is unchanged; preference validation, not a display label, rejects unknown adapters. `gameModeName`, `gameScopeName`, saved
machine tokens, ASCII basenames and timing integers are unchanged and remain outside this catalog. No low-level preferences
header imports this UI catalog. A human scope label is not an adapter parser, identity proof, complete-detection result or
permission to scan; foreign-platform or unknown detection still cannot imply game exit.

The argument-free `TerminalGameFieldMessageRequest` and four wrappers separately provide source-review metadata, complete
English ASCII/disabled recovery, original literal tone, bounded line/row layout and transactional refusal. They accept no
target basename or measured data. They do not localize a mode token, numeric value, input or complete review envelope; a
`ms` label does not itself bind a displayed number into a quantity. Existing atomic-quantity primitives and later complete
field integration remain distinct. Ordinary native code still calls no typed renderer and loads no Unicode backend.

Fixtures check all 144 texts, stable unique keys, exact field order/English/metadata/protected tokens and no parameters;
three order/three direction/five width modes, plain/paint equivalence, source/control/cell provenance and independent wrapped
rows; invalid language/key/tone/policy/row limits and unchanged outputs on every wrapper's refusal. The private fixed
predecessor Game harness checks **124416 complete frames / 44064 transitions, resulting frames and active/draft machine
serializations**. It uses three representative timing vectors (minimum/default/maximum), both scope adapters, all three
mode requests, clean/dirty drafts, idle/running-without-effective/running-frozen contexts, all six fields and four pages,
including a synthetic maximum basename and contextual Q/D/L/S. Save access stays empty; this is not exhaustive timing/input
space, actual store-concurrency, detector, game or worker qualification. Existing native store/CLI/PTY/supervisor tests
remain separate. Exact platform/sanitizer/privacy evidence is in the [execution ledger](architecture/execution-plan.md).

Game shell/review envelopes/editor/notices, other subpanels/dashboard/log/raw domains, effective native typed/data-owner/
deployment binding, human review and physical terminal/font/shaping/accessibility remain open. No game or mining process is
started by these APIs, no safety/experience/economic qualification is inferred and no production replacement/restart is
authorized.

[P-13w](game-panel-messages.md) subsequently extracts thirty-three literal Game shell/editor/limitation notices. This
nine-key field/scope domain and its historical evidence remain unchanged; dynamic envelopes/native gates remain separate.

[P-13x](game-value-messages.md) later extracts dynamic Game envelopes with separate human-scope and invariant-request
roles. Neither later extraction changes these label-domain historical results or activates native translations.
