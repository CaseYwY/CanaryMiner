# Background supervisor display sampling (P-03f / P-11l)

M-SUPERVISOR/M-GAME/M-ENERGY; R-SAFE-001/002, R-ENG-001 and R-GAME-004; T-INTENT/T-GAME/T-ENERGY; D-73.

The supervisor now performs child-stats HTTP, JSON parsing and its existing display NVML open/read/close operations on one owned background thread. The control loop consumes completed in-memory batches, so a slow display read no longer blocks its normal stop, worker-command or process-exit checks. This is a scheduling change to the existing display path, not a critical-safety source or permission to activate game mining.

## Fixed ownership and bounded handoff

`SupervisorSampling` starts at most once with copied ordered UUID/loopback-port targets (at most 256). Its optional reader factory, reader calls and reader destruction all execute on the sampling thread. The native reader uses the existing loopback-only `/api/v1/stats` client and display `Nvml` adapter. No reader borrows the supervisor's workers, views, session intent or settings. The production factory is internal; no CLI/plugin or settings-loading hook is added.

There is exactly one pending/in-flight batch **or** one unconsumed immutable result. A new request is refused until the previous result is consumed. Requests freeze every worker incarnation; zero skips an inactive slot. Readers visit active slots in order, preserving one ordered power-observation sequence. A slow device can delay the batch's other display values, but cannot create a queue, overlap driver reads or block the supervisor's command loop. The existing HTTP response allocation bound remains 4 MiB per call; original parsed display payloads stay private in memory.

The supervisor applies only results whose captured worker generation still matches the current active incarnation. A worker restart cannot relabel an old response as the replacement's counters or power. Cadence remains 500 ms in dashboard mode and 250 ms in plain mode, now measured from result consumption with no catch-up burst. Factory/reader exceptions terminate this sampler without automatic reconstruction; prior display values keep their original age.

`requestStop()` cancels admission, queued requests and result publication using only a short handoff lock. No lock spans factory/native/HTTP/parser calls or destruction. Cancellation is checked between native operations and devices. Already executing synchronous calls may finish late, but their results are discarded. Reader teardown joins after worker drain/control stop; member destruction also places controlled-fleet revocation before the sampler join on an unexpected exception. No detached thread can outlive its target storage.

## Original times and energy ordering

Stats retain the original loopback-receipt time, before parsing/publication; this is an observed counter time, not a pool acknowledgement timestamp. Accepted-history attribution uses that original UTC second. Failed stats polls break the rate-average sequence instead of repeatedly integrating cached rates.

Power retains original beginning/end clocks around its native open/read interval. Only a matching UUID, valid power read and ordered interval of at most 1000 ms on both clocks with at most 100 ms divergence can supply a known GPU-board power point. Missing or overlong reads supply missing power, never zero. Display telemetry expires after 2000 ms and is checked on ordinary loop ticks, not just on a later successful sample. The legacy display adapter's overall `valid` flag still does not certify every temperature/fan field; complete safety uses the separate [raw safety path](safety-telemetry.md).

Both energy consumers receive the original power beginning, not delivery time. All readings in a batch are consumed in original slot/read order. While a batch is outstanding, the durable capture's time-advancing `tick` is deferred; its memory-only review remains responsive. After consumption the capture may advance to current time, and only then may the next batch be dispatched. This preserves the existing capture's global ordering contract without pretending delayed originals were sampled now. No pending batch extrapolates an energy tail. Invalid original clocks cut durable continuity and stop the session-energy accumulator; missing power bypasses interval decimation so it can break held-power coverage.

## Verification and remaining boundaries

CPU tests use owned loopback HTTP and injected blocking/throwing readers, with native driver loading disabled in the test translation unit. They check fixed one-flight/result capacity, immutable generations/times, stop-before-start, cancellation between devices, discarded late results, blocked/null/throwing factory/reader paths and background-only construction/read/destruction. An actual `Supervisor` over a synthetic fleet must continue multiple control ticks while its reader is deliberately blocked, then revoke before the reader is released, including exceptional destruction. A separate two-device capture probe checks original timestamps, delayed delivery, ordered submit/tick handoff, missing power, UUID substitution and overlong reads.

Worker-session, supervisor stop/restart-budget, accepted-history and session-energy regressions cover the surrounding integration. Final platform counts and corrections are recorded in the [execution ledger](architecture/execution-plan.md).

Windows builds the sampler, worker-session, supervisor, history, session-energy and CPU CLI-host targets, then runs `supervisor_sampling|game_worker_session|product_supervisor|product_history|session_energy|native_build_recipe|architecture_contract`. Linux directly rebuilds the five corresponding C++ test translation units, including the changed inline supervisor/sampler, with `-std=c++17 -Isrc -O1 -Wall -Wextra -Werror -pthread` and unchanged supporting objects. Its sanitizer variant adds `-g -fsanitize=address,undefined -fno-omit-frame-pointer`, reuses instrumented supporting objects and enables leak detection without suppressions. The first Linux compilation stopped on test indentation and temporary-vector diagnostics; both were corrected without disabling warnings. The initial 49 checks expanded to 55 for missing/substituted/overlong power and then 60 for blocked construction and exceptional teardown ordering.

Final Windows focused CTest passes **7/7**: sampling **60**, worker-session **126**, supervisor **264**, history **290** and session-energy **233** checks, plus native-recipe and architecture guards. Linux ordinary and final **ASan+UBSan with leak detection** runs each pass **60/126/251/290/233** with zero failures; the supervisor count differs because Windows additionally exercises native handle inheritance. Linux actual-PTY settings/history scenarios and the **24** session-energy checks also pass using the rebuilt supervisor and existing unchanged idle-settings host. Architecture/import guards pass separately. These are synthetic CPU/owned-process results.

This thread isolation does **not** certify a hard process-exit deadline for a permanently stalled driver/kernel call: the owned thread is joined after worker stop, and cannot safely be abandoned. Helper-process isolation/global quarantine, loader/dependency trust and physical stop-latency qualification remain required. The existing synchronous settings persistence, console output and other storage paths retain their independent blocking limits. Complete safety-field/threshold-source qualification, ordinary protected fleet activation and integrated GPU/game acceptance remain open.
