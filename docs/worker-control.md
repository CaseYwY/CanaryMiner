# Fenced worker commands and boundary receipts (P-11e)

M-GAME/M-SUPERVISOR; R-GAME-004/005/006 and R-SAFE-001/002; T-GAME/T-INTENT; D-66. This slice supplies the private command protocol, a parent-side single-flight issuer and a worker-side memory gate for the [cooperative run-loop boundary](work-pause.md). They perform no process launch or game-policy evaluation. Ordinary miner startup still installs no gate; its existing stdin watcher remains EOF-stop only.

## Frozen worker incarnation and bounded frames

Each endpoint receives one frozen `WorkerControlBinding`: a 128-bit lowercase-hex parent-session key, an existing explicit session epoch, a slot (0..255), a nonzero worker generation and a separate 128-bit worker-incarnation key. Keys must be provisioned from private OS entropy by the future parent owner, never from wallet, account, device identity or a reusable settings value. This module validates the format; it does not provision keys or prove a caller's process ownership. Test keys are explicitly synthetic. There is no reset/rebind API, and a new parent epoch cannot revive an issuer borrowing an older token.

`CMWC1` commands contain that entire binding, a contiguous nonzero revision, original issued/deadline monotonic milliseconds, and exactly Pause or Run. `CMWA1` receipts echo the full command, a receipt kind and the original worker observation time. ASCII tokens, canonical unsigned decimal syntax, exact field counts and one LF are required; CR, NUL, alternate numeric forms, unknown versions and trailing fields reject. A frame is at most **384 bytes**, a feed at most **4096 bytes / 16 completed frames**, and the fragment accumulator has fixed capacity. Partial input never becomes a command, and an overflow/callback failure permanently fails that framer.

All times belong to the same host/boot monotonic domain. The default clock is `steady_clock` in both endpoints; a future transport must preserve that domain rather than translate issuance into receipt time. An issued command must already be valid when received, with a positive lease no longer than **5000 ms**. The gate also allows at most 5000 ms for its first command. Reversal, future issuance, exact-deadline expiry, malformed input, a binding mismatch, a skipped/old revision or changed content under the same revision removes eligibility. Exact duplicate current commands preserve their original deadline and receipt time. A terminal gate cannot accept a later renewal.

Five seconds is a protocol ceiling, not a game/safety freshness allowance: a supervisor must shorten every Run lease to the remaining validity of all source and policy evidence. Expiry is checked on receive, observation and worker-boundary reads, including while no new bytes arrive. A running search/source/preparation operation remains cooperatively bounded by its actual completion, not asynchronously preempted at the timestamp.

## Receipt is distinct from quiescence

The gate begins held. The first command must be Pause, and Run is refused until the worker has actually reported an initial drained pause boundary. An **Accepted** receipt only says that the exact command reached the gate. A **Paused** receipt is legal only for Pause and is published by the worker after the complete-work/drain/accounting boundary. The original Accepted observation may advance once to the actual Paused observation; repeated reads do not renew it. A Run Accepted receipt makes no claim that GPU work has started.

The worker's control read returns Run, Pause, Stop or Fault atomically under its memory-state lock. Pause heartbeats arriving while already held receive a new Paused receipt through `pauseHeld`, without another productive-time transition or manufactured search. If a new Pause revokes Run during the resume notification, the shared helper refreezes accounting and remains at the boundary before doing new work. Stop and Fault similarly prevent release; faults use the existing internal 11 → product fault 8 path, while terminal EOF/operator stop uses the ordinary stop path. Independent user stop retains priority.

The gate serializes only bounded in-memory state/clock operations. Parsing happens before state admission; the default clock performs no network, device, file or callback I/O. Injected clocks must obey that same memory-only contract. This is not a hard wall-time guarantee for mutex scheduling or allocation. No writer, pipe or logging callback runs under the gate mutex.

## Parent single-flight and stale evidence

`WorkerControlIssuer` borrows the existing `SessionIntent`/token and is single-use on one parent control thread. Only one command slot may be outstanding. Pause remains outstanding after Accepted and settles only with its matching Paused receipt; Run settles with Accepted. Issuing another command immediately removes the earlier pause proof from current use. An exact historical settled receipt can be recognized as a duplicate but cannot settle a newer command, change its deadline or refresh pause authority.

Receipts must exactly match the binding, directive, revision and original command times, and their observation must lie within the original lease and no later than receipt time. Invalid evidence latches refusal. Timeout/stop keeps an unresolved command slot; a matching late receipt may settle that command bookkeeping, but cannot revive authority. Settling a command never proves worker exit, joins a process, replaces an unresolved helper or clears the lifetime game/profit lock. Current pause evidence is obtained via `paused(now)`, not by treating a retained snapshot as permission.

The parent still has to retain the same [GameRuntime](game-runtime.md) across worker incarnations and settings review. This protocol is a local fencing contract, not independent game qualification or authentication against an arbitrary same-user process. Only an explicitly admitted, privately paired owned transport may carry it.

## Verification and remaining integration

The CPU suite exercises strict/maximal schemas, every frame split, partial/oversized/malformed input, callback failure, frozen binding, initial quiescence, pause renewal, accepted-versus-paused receipts, exact replay, receipt substitution, one-flight fencing, terminal expiry, clock faults and old-token non-revival. Concurrent receipt/worker observations are exercised with a terminal stop. The actual shared-loop CPU fixture additionally installs the real gate: before-setup failure, initial hold, completed work before a later pause, fresh resume, stopped/faulted held workers and unchanged null-control behavior.

An owned native CPU probe exchanges the real framed protocol over OS stdin/stdout pipes on both platforms. It checks fragmented identity frames, Run receipt followed by a drained pause, old-Run replay after a newer pause, idle lease expiry, a half-written Run that cannot renew authority, overflow, foreign identity and EOF mid-frame. Its bounded blocking I/O and parent-driven join are fixture-only, not a production pipe/deadline implementation. Ordinary-source admission still runs separately with aborting device-loader/socket wrappers on Linux; ordinary artifacts exclude the test source seam.
