# Native OpenSSL record steps (P-12b)

M-TLS; R-TLS-003/004; T-TLS/T-INTENT/T-RELEASE; D-93.

**Development, independently default off, not a pool connection factory or release capability.** `PearlTlsStream` now performs real native OpenSSL TLS handshakes and record processing over an explicitly borrowed, already connected byte channel. The ordinary miner does not link or construct it. SSL configuration, native DNS/connect ownership, fallback consent, secure presets, donation routing and production packaging remain absent. Windows currently returns Unavailable for an enabled request; its successful default-off tests are not Schannel evidence.

The explicit Linux build option is `CANARY_ENABLE_POOL_TLS_OPENSSL=ON`, with separately supplied **OpenSSL 3.5+** development packages. Configure downloads nothing. This version floor is an API/support baseline, not security approval for an unserviced patch. The default library needs no TLS dependency and can neither encrypt nor silently send plaintext as a substitute.

## Ownership and state

One owner supplies the raw transport, an immutable enabled policy, reference identity, explicit/system anchors, one absolute handshake deadline, cancellation and original monotonic instants. No method resolves a name, opens a socket, changes a preset, waits for readiness, starts a worker, loads a client key or touches the installed miner. The raw channel promises bounded nonblocking steps after its one successful `setNonblocking(true)`; it is never restored to blocking mode.

An enabled, structurally valid Begin adopts close authority for that channel's reserved lifetime. A dormant/disabled object's destruction never closes an unrelated borrowed channel. Explicit abort, including before Begin, is terminal; later Begin or late data cannot revive it. Cancellation and clock rollback latch failure, and cancellation is checked around raw IO and before application-byte publication. Never reopen/reassign the adopted raw object underneath a terminal stream. All native context operations and destruction belong to one thread; only the cancellation flag is shared.

The states are Dormant, Handshaking, VerifiedOpen, Closed and Failed. Final handshake output must be completely flushed before VerifiedOpen. That state asserts the implemented **chain, validity, server usage and reference-SAN checks**, not qualified revocation, bounded OS processing, a real endpoint or a production mining permit.

## Verification policy, without credential disclosure

Each connection owns a fresh client context, peer verification, TLS 1.2 minimum, no TLS compression, no legacy renegotiation, no client session cache and no client certificate/private-key source. No early-data operation is used. DNS references use SNI and native SAN matching, with partial-label wildcards and common-name fallback prohibited. Unbracketed IPv4/IPv6 references use native IP-SAN checking, never a numeric DNS SAN or selected socket address substituted for the configured identity. Malformed names/CA input fail rather than retrying with a weaker identity/trust mode.

Empty CA bytes select native OpenSSL default trust paths. Explicit bounded PEM bytes instead populate that fresh context's **exclusive in-memory anchor store**, without adding ordinary roots or modifying OS stores. Only complete certificate PEM blocks and whitespace are accepted; each admitted anchor must be a self-signed CA with a valid self-signature. A leaf, incomplete/empty bundle, wrong anchor, trailing junk or malformed certificate is not a reason to use system trust. This initial API supplies anchors, not user configuration persistence or automatic enrollment.

**Revocation remains a release gate.** This OpenSSL slice does not obtain/qualify CRL/OCSP evidence, enable automatic AIA fetching or claim equivalence with Windows native trust. No missing revocation input is reported as a passed revocation check. The [Windows private-trust study](research/schannel-private-trust.md) preserves normal automatic Schannel verification and describes the separate exclusive-memory-store/strict revocation/SSL-policy obligations; client `hRootStore` is not a private-CA mechanism. Windows custom trust and native record handling remain unimplemented.

## Finite progress and exact bytes

OpenSSL uses a bounded BIO pair with **64-KiB input and output halves**, a **64-KiB maximum peer certificate list**, depth ten, **16-KiB plaintext/output chunks**, and separate owned pending-ciphertext, pending-plaintext and stable-write storage. The total handshake accepts at most 512 KiB of combined raw traffic and 8192 step calls under the original deadline. These are application-owned input/progress bounds, not a cap on all native-library allocations or CPU time.

Every step performs a bounded amount of raw IO without a wait. WANT_READ/WANT_WRITE preserve their actual dependency. Outgoing control tokens are flushed before waiting for input; with AUTO_RETRY off, already buffered records are retried before reading/waiting on the raw channel. `bufferedRead()` includes saved plaintext, internal records, output/control progress and observed raw EOF, not a promise of a complete JSON line. TLS 1.3 key-update traffic is exercised without inventing plaintext or treating empty control progress as EOF.

Writes copy at most one 16-KiB chunk into stable owned storage. Until that operation completes, retries must preserve the caller's original pointer/length and chunk content. Partial raw sends retain the one generated ciphertext plus offset; the same accepted chunk is not encrypted again. Positive application consumption is reported only after all its owned ciphertext is flushed. A failed/cancelled write can already have emitted wire bytes while reporting zero application consumption; the canonical source's [P-12a attempted-write Unknown rule](pool-progress-io.md) remains essential. A local flush is never a pool acknowledgement.

Reads preserve exact pending plaintext across smaller caller buffers. Authenticated close-notify produces EndOfStream; truncated transport EOF is an error. Local abort closes immediately without a TLS shutdown exchange and must not be described as authenticated peer closure. No failure downgrades or replays a share.

## Executed scope and remaining gates

`test_pearl_tls_stream` uses ephemeral EC keys, distinct synthetic CA/server certificates and a real OpenSSL server entirely **in memory**. It creates no socket, file, public connection, root installation, account or GPU workload. Tests cover chain/name/issuer/expiry/future-validity/usage failures, DNS SNI, IPv4/IPv6 SANs versus numeric DNS SANs, malformed/leaf anchors, TLS 1.1 refusal and TLS 1.2/1.3, one-/seven-byte fragments, final-token backpressure, stable retries/encrypt-once output, multi-record exact transfer, saved plaintext, key updates, client-authentication refusal without identity, truncation versus clean closure, throwing raw operations, deadline/clock/cancellation and late revival refusal.

A test-only transport adapter also runs actual `PearlPoolSource` authorization, canonical job parsing, exact request correlation and submission over those encrypted records. This regression first failed because buffered control/application records were hidden behind WANT_READ; the implementation now retries the owned BIO input before requiring new raw readiness. A separate fixture error used a fixed submit response ID instead of the actual request; the server now echoes the exact ID. No synthetic proof represents official proof acceptance. The default-off fixture separately proves no TLS setup/IO, terminal stop and dormant-channel preservation.

Final platform/regression results are recorded in the execution ledger. Own-code sanitizer coverage does not instrument the system OpenSSL library. Real Schannel, qualified revocation, cancellable DNS/connect/native trust setup, native process isolation, clean-machine dependency servicing/deployment, secure URL/settings/fallback, donation TLS and physical/production qualification remain open. In particular, neither supplied monotonic instants nor nonblocking socket calls establish a hard deadline for synchronous trust-file loading or native cryptographic/OS work; ordinary job-intake activation is not supplied by this API.

The external OpenSSL library is uninstrumented. The Linux default-off executable has no undefined SSL/X509/BIO/PEM dependency symbols. Final architecture/import/staged/history privacy and diff checks pass. The P-12a seven-suite Linux canonical/protocol regression is unchanged and retained; Linux CMake/native Schannel/real endpoint and release qualification are not claimed.
