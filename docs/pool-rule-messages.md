# Complete before/after pool-rule review envelopes (P-13ac)

M-I18N/M-UI; R-I18N-001/002; T-I18N/T-UI/T-CONFIG/T-PRIVACY; D-128.

**English-only native source extraction and independent typed drafts.** Eight stable `pool.rule.*` keys in sixteen packs
(128 templates) cover complete Before/After mode/TLS/TCP/plaintext-consent rows, with distinct both/TLS-only/TCP-only/neither
endpoint forms. Non-English entries remain machine-assisted drafts, not reviewed security language or effective native UI.
Missing-endpoint descriptions are localized literal text in those templates, not an invented invariant endpoint argument.

The native panel chooses the complete English key from original endpoint presence and supplies unchanged mode, set endpoint
and YES/off consent tokens. It no longer flattens a full rule into a generic human argument or joins a translated prefix to
machine bytes. Exact old English rows, focus/scrolling, active/draft JSON, review/save/cancel, fixed confirmation phrases,
independent user/donation scopes and stop remain unchanged. Raw validation/store/callback errors are not interpreted.
The earlier pool label/notice/literal-shell/field-value domains retain their separate historical evidence.

English expansion is once-only, with at most four exactly named nonempty printable-ASCII arguments, 300 bytes per original
and bounded complete output. Independent `TerminalPoolRuleMessageRequest` layout/wrap/paint wrappers require every argument
to be invariant and nonempty, cap both original/recovery at 300, and delegate exact parameter matching, control/UTF-8/role/
policy validation and complete recovery to the shared pipeline. Optional keys accept only their actual endpoint parameters;
they cannot silently fill a missing argument with an empty/zero endpoint. Too-wide atomic machine bytes are never split or
partially clipped, and failed wrapping publishes no rows. Requested/source review, literal/argument tone and source/control/
cell provenance remain intact.

These are **opaque display** contracts, not URL/mode/consent validators, verified-peer facts, action receipts or source
qualification. Nonempty ASCII may still be an invalid endpoint; the existing parser and owners retain sole admission
authority. A before/after consent flag describes the original declaration, not authority to downgrade, connect or inherit
user permission into donation. Native TLS still refuses ordinary startup until separately qualified. No renderer starts a
helper, accesses a store, sends protocol bytes, changes donation or restarts a worker; ordinary code still calls no typed
renderer or ICU, and preferences import no UI catalog.

Fixtures check all 128 complete templates, exact English/unique keys/parameter/review/RTL/TLS/TCP parity, independent
endpoint-presence forms, one-pass/reordered/300-byte expansion, every layout/direction/width/plain/paint/wrapped-row mode,
each argument's empty/non-invariant/non-ASCII/control/oversized/substituted-recovery refusal and unchanged outputs across all
four wrappers. Native memory-only rows additionally cover all three modes, all four endpoint-presence combinations and both
consent flags against the original literal format, with unchanged active/draft JSON. Some combinations are deliberately
inconsistent developer-only render states; this is not acceptance of those preferences. The fixed-predecessor comparison
remains **258048 frames / 91392 contextual transitions, resulting frames and declaration serializations**, using the same
representative valid vectors and empty save access. Native store/CLI/PTY/fallback/transport regressions remain separate.
Exact platform/sanitizer/privacy evidence is in the [execution ledger](architecture/execution-plan.md).

Raw validation/other subpanels/dashboard/log domains, effective typed native/data-owner/deployment, human review and physical
terminal/font/shaping/accessibility remain open. Actual TLS/trust/egress/fallback/donation/deployment, global quarantine and
real GPU/game/financial/power/safety/release gates remain unqualified.
