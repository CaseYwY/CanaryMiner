# Independent pool-security declarations (P-12g)

M-UI/M-CONFIG/M-TLS; R-UI-007, R-TLS-001/002/003/004; T-UI/T-CONFIG/T-TLS/T-INTENT/T-PRIVACY; D-98.

**Configured declarations, not live TLS or fallback activation.** S → Pools and TLS opens the same native editor as the idle `settings` command. It saves only `pool-security-preferences.json`, separately from UI/runtime/mining credentials. No menu, review or save constructs a helper, resolves DNS, connects, changes the running miner, replaces a pool, or rewrites donation identity/scheduling/protocol.

## Endpoint and scope contract

One to eight user-pool slots and one separate donation declaration each retain their own mode, TLS URL, optional plaintext URL and explicit plaintext consent. Existing/missing declarations default to **unchanged**; this preserves intentional legacy TCP compatibility rather than inventing a working TLS migration. Newly added user slots default to **strict TLS**, with no endpoint or consent. No published candidate is prefilled or represented as verified. These slots are not yet bound to production configured pool/account identities.

The declaration parser accepts explicit `stratum+ssl://DNS:PORT` and `stratum+tcp://DNS:PORT` only. It bounds URLs, DNS labels and total name length, normalizes ASCII DNS case in the editor, and stores canonical lowercase names with an explicit canonical port in 1..65535. Credentials, userinfo, paths, queries, fragments, backslashes, controls, non-ASCII names, bracketed addresses and numeric IP identities refuse. Punycode DNS can be explicitly supplied; no IDNA guessing occurs. IP support remains a separately qualified native identity capability, not a DNS substitution. Errors do not echo rejected endpoints or secrets.

**Unchanged**, **strict TLS**, and **prefer TLS** are distinct. Prefer TLS does not itself authorize plaintext. Consent requires both explicit endpoints and the exact phrase **ALLOW PLAINTEXT** in a contextual editor. Changing either endpoint or mode revokes consent in the draft. The compact confirmation shows that plaintext exposes logins/proofs and that a network attacker can trigger fallback. All values, before/after records (including removed slots) and donation's independent scope remain available in the scrollable final review; Enter saves, Esc edits/cancels, dirty leave permits discard, and Ctrl+C/Q stop without saving. Q/D/L/S typed inside a field remain input.

The one-use pure `PoolFallbackGate` freezes one declaration/scope/slot/attempt. Only exact matching, pre-verification, pre-application DNS/connect/network-timeout failure evidence with an explicit **Resolve or Connect phase** can select that slot's separately consented TCP endpoint. A generic helper, handshake or trust timeout is not network evidence. Certificate/name/trust failure, unknown/protocol/unavailable state, clock fault, stop/cancel, explicit strict SSL input, an already verified connection or any application write attempt refuses terminally. A wrong/stale attempt consumes the gate rather than permitting a later substituted result. This is **reference bookkeeping**, not a native failure classifier, connection attempt, credential-export authority or runtime fallback implementation.

Donation cannot inherit any user endpoint/permission. There is still no qualified fixed secure donation tuple; the gate therefore **refuses donation fallback even when a separate prospective declaration contains consent**. Such consent is not capability and cannot select a replacement fee peer/account. The existing donation constants, debt, schedule, destination, user/donor counters and protocol bytes are unchanged. F2Pool/donation TLS ports must not be guessed or changed to another pool.

## Save, startup and current-session behavior

The [v1 schema](../config/pool-security-preferences-v1.schema.json) rejects unknown/duplicate/missing fields and unsupported versions; the native document limit is 8 KiB and numeric tokens remain strict. `LocalPreferencesStore` opens bounded regular files without following the final symlink/reparse point, holds the existing OS-owned preference lease for save, compares the exact loaded original, uses an exclusive private temporary with flush/fsync and atomic replacement, and reports ambiguous directory-sync outcomes as requiring reopen. Failed load invalidates save admission; stale writers and malformed/orphan targets are preserved rather than repaired. Parent-directory policy, physical durability and arbitrary kernel/disk-stall bounds are not qualified by these small synchronous saves.

Pooled parent CLI startup (including research/evidence modes, not just ordinary game/economic defaults) reads this separate declaration before device setup or worker creation. A malformed file or **any requested TLS mode**, including donation-only, refuses instead of silently mining TCP while displaying secure intent. The development [retained helper](pool-tls-stream.md) is not an ordinary-runtime qualification. Missing/unchanged declarations preserve ordinary legacy TCP with an explicit unencrypted-compatibility warning. A direct CLI/config `stratum+ssl://` remains a strict refusal until ordinary binding exists; its error no longer suggests changing to TCP. Help/idle settings and offline benchmarks do not require a pool transport or activate TLS.

Saving from an existing session changes only future declarations; existing connections and child retries remain frozen. The optional supervisor store path is a local editor target, not a factory or policy activation input. No ordinary miner links or constructs a retained TLS process transport through this panel.

## Validation and unqualified work

Native host tests cover strict URL/schema/type/size/port negatives, exact output preservation, independent slots/donation, all allowed/forbidden fallback classes, wrong-attempt/strict/verified/application/stop refusal, endpoint-change revocation, private store conflict/lock/invalid-version/symlink/directory handling, contextual confirmation/save/discard and short/narrow complete-review navigation. Real host-stub CLI tests prove refusal before the fixture's forbidden-device sentinel, unchanged files and no private endpoint echo. POSIX PTY tests exercise actual idle save/review/discard/external conflict/resize/SIGINT and a synthetic running supervisor without extra child starts. No real TLS peer, public pool, wallet, GPU or game is used by this batch.

Exact platform counts and repetitions are in the [execution ledger](architecture/execution-plan.md). Ordinary TLS/fallback routing, full configuration/CLI migration, secure qualified presets, normal native trust/egress/session-cache/IP/intermediate/deployment, global helper isolation, real donation TLS and public-pool/GPU/game/release acceptance remain open. Neither declarations nor a CPU gate result may be relabeled as passing those gates.
