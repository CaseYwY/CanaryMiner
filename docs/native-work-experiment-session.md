# Native fleet measurement-to-economic sessions (P-09g)

M-PROFILES/M-OPTIMIZER/M-SUPERVISOR; R-PRO-001/002/003, R-OPT-001/003 and R-SAFE-001/002; T-PROFILES/T-OPTIMIZER/T-INTENT; D-89.

`GameWorkerSession` now optionally constructs the actual [experiment command owner](work-experiment-owner.md), its [parent reservation budget](work-experiment-budget.md) and the one-use economic handoff. Each economic slot may explicitly supply `GameExperimentPolicy`; absent means the preceding direct-economic path. This is native command/fleet integration with **SyntheticFixture** sample admission. Ordinary CLI factories, real sampling and native sample transport remain separate.

## Frozen parent owners and incarnation admission

The complete experiment command policy, reservation policy and existing work plan are frozen with the economic slot. Both experiment and economic leases must match the fleet lease. Command policy and reservation startup are validated before worker launch. Each slot retains its experiment budget alongside its evaluator and economic budget, outside all worker incarnations. The destruction order keeps those borrowed owners alive until every incarnation has been released.

Initial Pause still belongs to the native process owner and issuer. After its actual revision-1 Paused receipt is consumed, the session exposes the original receipt and current private worker binding to the sample coordinator. No experimental Run or economic admission is possible until a complete original baseline is consumed. The original initial command lease bounds this waiting state; missing baseline does not silently renew revision 1 or start a new experiment.

The baseline starts the real `WorkExperimentOwner`, which reserves the **whole** attempt before its first Run. Reservations, original parent clocks and previous admissions survive eligible native replacements. Refusal consumes no new reservation; an admitted failure keeps its reservation and attachment. A new native process or sample counter cannot reset these limits.

## Bounded control-thread sample inbox

`submitExperimentSample` queues at most one original sample for the matching current incarnation. It verifies the complete private worker binding: parent/worker keys, epoch, slot and worker generation. A foreign binding is rejected without replacing or revoking the current source. It is memory-only and does not issue or acknowledge worker commands. Full returns backpressure without replacing the queued original; the producer must retain its unconsumed source record rather than skip or relabel a sequence. Before readiness it returns NotReady; after handoff it is Inactive. Wrong-incarnation data cannot enter a replacement. A current-incarnation sequence discontinuity faults the whole fleet.

The next tick first admits current aggregate safety/game conditions and consumes the actual original native receipt through the **current** owner. Only then does it consume the pending sample. Queuing does not restamp either sample clock, update installed wait, renew source age or grant qualification. The original complete-plan fingerprint, counter epoch, source clocks, exact work/power, source freshness and current safety/game/drift still pass through the existing measurement owner. A sample older than a newly consumed settlement or inconsistent with the installed wait refuses rather than being rewritten.

The fixture producer binds samples to explicit synthetic identity/plan/conditions. The raw [P-09f alignment record](work-power-alignment.md) is not automatically converted here: sensor support, full source identity/drift qualification, native sample sequencing and cross-thread/process transport are still required for a production source.

## Exclusive commands and one-use transfer

After baseline admission, only the experiment owner calls issue/ack. Each returned command is submitted once to the same actual `WorkerProcessOwner`. Accepted remains pending; the actual original WaitApplied/Paused settles it. Source/permission expiry, unsafe/game/drift conditions, invalid sample/sequence, transport failure, or loss of the worker during measurement revokes **every** fleet channel immediately through the session's existing halt path. No second Pause overwrites a pending Run.

Final Paused plus the final complete sample freezes the measurement and accounts completed observations in the parent reservation. The session then calls the successor's `startAfterMeasurement` on that actual owner. The one-use release transfers the same issuer; the experiment becomes inert, and all subsequent receipts/commands belong exclusively to the economic owner. The exact record, original initial admission, economic parent-slot attachment, cumulative clocks and strict post-handoff study barrier remain intact. Handoff failure halts the whole group and cannot roll back into an experiment.

Economic submissions for this path require the **entire current captured work record**, not merely the same plan, model or summary. `sameWorkProfileInput` compares plan, parent/counter identity, all original sample fields/times/counters and every window index. A built profile with the same rates or differences but shifted timestamps/counter origin is not interchangeable. Previous-incarnation profiles cannot be reused after a new capture. Profile construction/economic calculation still use the established explicit qualification gates; callers cannot inject a finished economic study.

The existing independent evaluator schedule starts with the parent and remains alive across measurement and replacement. A ticket issued before or at handoff cannot be restamped into a later evaluation; it must settle under its existing ownership/retry rules. The fleet does not reset the evaluator to force a fresh ticket.

## Reaping and retained budgets

Replacement requires actual native Exited, real reaping, exit 1, complete original settlement before disconnect/exit, a successfully started economic successor and its normal retirement. Only then does the session retire the experiment attachment with the **same stopped, settled issuer**. Both budgets retain totals/history and the evaluator retains its own lifecycle. Retired native objects stay owned until final joining, preventing overlap or premature destruction.

Failure/exit during measurement revokes the whole group and cannot retry. Exit 0/7/8, unknown settlement or unproven reaping cannot retire an experiment for replacement. Operator stop preserves reservations/records and revokes first; it does not create a new admission. No automatic relaunch, refund, game resume, driver recovery or ordinary CLI activation is introduced.
