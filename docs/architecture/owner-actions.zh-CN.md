# 人工输入与操作清单

## 什么时候需要你操作

**当前软件收尾可以继续，不需要先交齐下面的资料。** 自动构建、CPU/合成/本地 TLS 测试、代码集成和已授权开发分支的 Git 提交由执行者负责，不要求你代跑或手工提交。一个模块缺真实来源或实机验收，不等于其他软件工作全部被阻塞。

已完成实现、普通入口是否接通以及外部验收须分别汇报，见[进度核查](progress-audit.md)。按[模块交付规则](execution-plan.md#module-delivery-rule-current-user-instruction)完成一个可独立使用的功能再提交；不能仅打开开发宏或删除拒绝检查来制造“已经启用”。

本清单记录当前规划已知的人工边界，不是要求立即提供所有数据，也不承诺未来不会发现新问题。实际遇到阻塞时，须单独说明：**哪个模块、最少需要什么、用途、可否公开、没有它影响什么**。能从官方公开资料确认的内容先自行研究；不得把这些查证工作一概转交给用户。

## 私密资料如何提供

- 不在聊天、公开仓库、提交信息、公共样例或日志里发送密码、令牌、钱包/账户标识、原始财务导出、私人曲线和完整机器标识。
- 最初的来源/格式讨论只需模式、公开文档、字段名/单位及明确标为合成的结构样例；不要为了本清单提前导出账户数据。
- 必须登录的步骤由你在合适的私密界面完成。确需 API 令牌等秘密时，使用专用私密输入卡片，不贴聊天；执行者不得打印、记录或复制进项目。
- 用户配置中的必要实际值在本机私有配置/审阅流程使用，不写入贡献样例。需要引用界面问题时先裁切、脱敏，不能提交原始 HAR、cookie、私有 URL 或请求头。
- 只请求当前模块真正需要的最小权限。拒绝某项实源、实机或发布操作时，该验收保持未完成；不以绕过保护、假造数据或重复开发已完成核心代替它。
