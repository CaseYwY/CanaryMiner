# 架构书：中文执行入口

英文主文档面向公开仓库；这里帮助快速确认要求，具体合同以对应编号为准。**架构设计不等于功能已实现。**

## 最终确定的收益口径

- 接受数：滚动24小时／7天／30天／从本地开始记录以来的累计；注明覆盖范围，捐赠份额分开。
- 币价：近1小时等时间均价＋最新报价，明确来源、币种、更新时间和过期状态。
- 今日预估：所选时区的今日已记账收入＋今天剩余时间预测，说明假设；不是一律乘24小时。
- 实际收入：矿池能够归属的实际代币入账，显示近24小时和累计；余额、提现和接受份额不能充当实际收入。
- **主面板按最新价格折算产出参考价值。逐笔估值仅为详情中的可选历史参考。** 此为最终确认，覆盖此前的逐笔主面板方案。
- 无法知道是否已出售；不把估值称为实收美元、已实现利润或当前持仓。USDT也不等于USD，美元显示需要有效换算数据。
- 不填写电价就完全隐藏净利润；填写后允许明确标注GPU板卡功耗口径的估算，但不保证整机实际净赚。

## 功能与模块

1. 原生终端设置：S进入、方向键/Tab导航、空格/回车编辑、V/F2审阅、显式保存、Esc返回；停止优先。
2. Details/Log：分别开关入口和页面，还能调整详情字段、日志级别/条数/时间/跟随；显示过滤不改变后台记录。
3. 收益自动调节：按实测曲线、电价、行情和收益校准挑选安全候选中的最高单位真实时间估算净收益，不是只追求算力或能效。
4. 多个时钟分别可调：采样、预热、测试时长/次数、价格窗口/刷新、经济复查、重测、过期/重试，不能混作一个频率。
5. 游戏：关闭联动／暂停挖矿／测试后共存；游戏体验合格后才在合格候选中择优，退出游戏恢复普通候选。Steam出现只能证明联动，不能证明游戏帧率。
6. TLS：优先安全连接，证书/域名验证；每个矿池先授权才可在规定连接故障后回退明文，证书错误不降级。
7. 多国电价：国家不是价格。规则、地区/供应商/套餐、币种、时区、账期、阶梯、峰谷、动态负价、税费等分开建模；复杂需量、预付费、光伏出口必须声明能力范围。
8. 多语言：首个国际化阶段的16个语言标识见终端规格，支持回退、宽字符、组合字符和RTL；不改变CLI/API键名、计费或资产身份。
9. 安全隐私：不复制本机路径、钱包、GPU标识、私有电价/曲线/实验结果；不自动重启/重载驱动，不隐式开机挖矿，不绕过反作弊或关闭游戏。

目前已完成P-01菜单基础、P-02的D/L开关与内容控制及财务展示合同，以及P-04的本地接受数观察历史（SQLite事务、24小时/7天/30天/累计、重启恢复及覆盖提示，`--no-history`可关闭本次记录）。观察记录不等于完整矿池账本：采样中断、退出尾段和会话之间的区间明确标为不确定，时钟异常时滚动统计显示不可用。详见[历史语义](../accepted-history.md)与[验证证据](../history-validation.md)。

财务展示通过的是合成输入测试，**尚未接入真实行情、实际收入或电费计算**；原生运行设置、TLS与其余模块按状态表继续分批实施。每批都要同步证据、脱敏扫描和提交；不能把设计清单当作已经可运行的全部功能。

P-03a已补上[会话停止与启动脚本保护](../session-intent.md)：停止撤销本会话授权，Q/正常退出不重启，强制停止返回7，故障锁定返回8且外层不得重试；高级脚本仅对运行错误1有限次重试。游戏/经济优先级目前是纯合同测试，不是已经启用的自动控制。

P-03b新增[完整工作批次间等待](../work-wait.md)的CLI实现：`--work-wait-ms 0..1000`，默认0，不是占空比，不调整硬件频率；完成与结算当前批次后才等待，等待可响应停止，之后重新获取工作。原生默认值控制由后续P-03c补上；真实GPU能耗和生产发布验证仍未完成，不承诺某个等待值一定赚钱或适合游戏。

P-03c已接入[原生运行默认值](../runtime-settings.md)：在“Automatic mining”或“Privacy”进入等待/历史记录设置，独立审阅、保存、取消，显示配置值、当前生效值和CLI覆盖。保存只影响下次显式启动，子进程崩溃重试也不偷换旧会话值；关闭记录不删除历史，数值输入中的Q不会退出。UI草稿与运行默认值分别保存。实时激活和更广泛配置变更审阅仍待实现。

[行情/收入接口调研](../research/market-and-credit-providers.md)记录了Gate的PEARL_USDT与PRL身份映射、Kraken直接USDT/USD汇率候选，以及Kryptex公开收益接口的归属/记录ID/时间粒度不足。实际收入不得用余额、提现或份额分摊补齐；相应行继续保持不可用。

P-06a新增[默认关闭的HTTPS基础与独立原生helper](../public-https.md)：严格证书/域名验证、固定公共GET、有界JSON/进程间响应和可终止的进程边界。Windows与Linux分别验证直接TLS和进程隔离场景，不为解决超时关闭证书或吊销检查。它不是网络沙箱；系统信任辅助请求、正式打包、行情适配/刷新/缓存和主面板仍待后续验证与接入，实际收入仍不可用。

P-06b新增[精确十进制、行情适配、缓存调度与原生只读展示](../market-data.md)：历史美元均价逐分钟对齐相乘后求均值，不使用“两个均价相乘”；来源、币种、观察时间、过期、覆盖和未知成交事件时间分开保留。后台任务有有限重试、独立时钟和停止后结果丢弃。蜡烛时间语义未验证，因此只允许明确标为合成的测试数据，生产监督器尚不启动行情任务；预览不会访问网络或启动矿工。实际收入、电价及完整规划仍待后续推进。

P-07a新增[可持久化的精确入账核心](../credit-ledger.md)：明确绑定资产、来源、worker/账户及代次、精度、记账时间与修订语义；重复不累加，更正按修订替换，覆盖不足不伪造零。修订保留首次来源快照，崩溃未提交事务会回滚；估值使用最新价格且不改写代币事实。当前只接受明确标为合成的来源合同，真实矿池仍不合格，收入面板仍未启用；后台采集、日历今日预测及其余模块继续实施。

P-05a/P-08a新增[时区、精确电量与声明式电价核心](../electricity-core.md)：明确选择UTC、固定标准偏移或默认关闭的离线版本化IANA数据，处理23/25小时日、半小时变更及跳过的日期；W·ms积分与费用保留精确分数，缺采样不补零。支持共享阶梯、真正的全量选档、峰谷/动态负价、简单费用/最低账单及纯整表双场景计算。复杂需量、预付费、出口抵扣和未实现计费规则明确拒绝。它不是已验证的供应商套餐、实时功耗采集、今日收益/净收益预测或自动优化；生产面板仍未启用财务功能。

P-07b新增[进程隔离的有界入账后台](../credit-owner.md)：父进程只接收带代次和票据的不可变快照，SQLite 打开、提交、查询和关闭均在独立原生 helper 中执行。队列满时明确回压，入队不等于保存；停止丢弃未确认排队任务，不发布迟到结果。若已提交却丢失确认，保留原批次并锁定待核对，只有显式重放相同内容才能幂等恢复，不能假称已回滚或自动复活采集。真实来源、持久待处理日志、恢复界面及生产激活仍待完成，收入面板继续不可用。

P-06c新增[原生手动／离线行情输入](../manual-market.md)：在“Market and timing”中分别填写PRL/USDT与USD/USDT、各自UTC参考时间、有效期和最大时间偏差，独立审阅保存。默认关闭，明确标为用户声明而非实时报价；单点输入不构成一小时均价。保存不会重启worker，也不会偷偷刷新参考时间；`--no-market`持续覆盖本次显示，时钟异常锁定为不可用。UI、运行默认值与手动行情分别保存；不启动网络采集、实际收入、净收益或优化。小型设置文件仍沿用同步保存路径，真实磁盘卡死时的停止期限和完整发布资格尚未验证。

P-07c新增[持久待核对日志与重启恢复](../credit-recovery.md)：默认在原生helper中先保存完整原批次，再允许写账，入账后保存确认回执。重启只检查，不自动重放；旧批次重试失败不能消除过去的不确定性。确认回执也须以只读方式核对当前账本，缺失或分歧不能重建成零记录。仍只接受合成合同；真实来源、采集游标、原生恢复／导入导出界面、父进程死亡后的helper隔离及生产激活尚未合格，收入面板仍不启用。
