# Shared progress and native Schannel record steps (P-12d)

M-TLS; R-TLS-003/004; T-TLS/T-INTENT/T-PRIVACY/T-RELEASE; D-95.

**Default-off development capability, not ordinary mining TLS activation.** The existing `PearlTlsStream` now uses one shared owner for raw nonblocking IO, stable pending writes, cancellation, monotonic deadlines, exact plaintext publication, final-ciphertext flushing and terminal closure. Private memory-only native engines implement OpenSSL or Windows Schannel behind that same owner. No miner factory, resolver, socket connection, SSL URL/preset, fallback, donation migration or release binary is added.

The explicit Windows option is `CANARY_ENABLE_POOL_TLS_SCHANNEL=ON`; it refuses other platforms. Windows compilation uses the declared modern Windows 10/1809 SDK baseline, real SDK `SCH_CREDENTIALS`/`TLS_PARAMETERS` declarations and `winternl.h`, not copied compatibility layouts. `SCHANNEL_USE_BLACKLISTS` exposes those SDK declarations; it is not a reason to fall back to deprecated credentials. Runtime OS/version/servicing support still needs a separate matrix. No system protocol/cipher registry setting or driver is changed.

## Separate normal and explicit development trust

Normal mode acquires outbound credentials with **automatic validation, no default client credentials and chain-excluding-root revocation checks**, and passes the original frozen ASCII DNS reference to SSPI/SNI. Every initial/continuation call requests stream/confidentiality and supplied credentials. No client certificate/key is supplied or selected, no name/CA/revocation ignore flag is set, and no client-identity store is enumerated. Negotiated protocol must be TLS 1.2 or 1.3; older protocols are disabled while OS cipher policy remains authoritative. A DNS SAN is required, so a common name alone cannot open the stream.

Normal automatic-trust positive validation and its auxiliary egress/blocking/session-cache behavior are **not qualified by this batch**. They must not be relabeled passed because another trust mode succeeds. No external TLS peer or trust-store installation was authorized or used for these fixtures.

The separate `windowsPrivateTrust` policy is development-only and also requires `CANARY_ENABLE_POOL_TLS_PRIVATE_TRUST`. It snapshots explicit memory anchors/support/CRLs, requires the same DNS reference, and prohibits a preconfigured leaf. After SSPI permits querying the remote certificate, the **actual peer DER** replaces the inspection leaf and must pass the [P-12c strict native chain/revocation/SSL DNS gate](pool-private-trust.md). Manual SSPI verification is used only for this explicitly selected path; local TLS completion alone never authenticates it. Empty/missing/expired/revoked/unknown material refuses without system-trust or plaintext fallback. It does not establish production equivalence with automatic OS trust. The configured supporting intermediates are available; automatic admission of a received private intermediate chain is not yet implemented/qualified here.

PEM `caPem` is not silently reinterpreted on Windows. Literal IP identity remains unavailable rather than substituting DNS or bypassing name checks. Linux rejects a Windows private-material policy instead of ignoring a platform-specific security request. No normal/custom policy switch or credential-cache reuse is inferred from a successful fixture.

## Native memory and output ownership

Schannel owns one credential/context lifetime on the single calling thread. SSPI-allocated tokens/alerts have matched RAII `FreeContextBuffer` cleanup, including allocation/copy exceptions. Even `SEC_E_OK` output must fully pass the shared raw-output offset before VerifiedOpen. Context attributes, actual remote certificate, negotiated protocol and bounded stream sizes are checked before opening. No crypto is implemented by this project.

Incoming encrypted storage and owned native record/output are bounded to 64 KiB; the shared outer owner retains its 16-KiB chunks, initial 512-KiB combined handshake traffic budget and 8192-call ceiling. Stream sizes determine the allowed plaintext chunk. `EncryptMessage` executes **once per chunk**; partial/raw would-block writes only advance retained ciphertext offsets. Positive plaintext consumption is published only after its complete owned output flush, never as a peer acknowledgement. The [attempted-write Unknown rule](pool-progress-io.md) remains necessary when failure/cancellation reports zero plaintext consumption.

Incomplete messages preserve input; extra bytes remain bounded and ordered. Successful zero-plaintext processing is progress, not EOF. `SEC_I_RENEGOTIATE` suspends application processing, preserves the modified SSPI token descriptor (without requiring EXTRA to exist), and re-enters negotiation with the same identity/credential restrictions. Application traffic reopens only after verification and final control-output flushing. Each new actual control phase has a fixed ten-second supplied-monotonic deadline, finite call/traffic budgets and no fragment renewal. The public state shows Handshaking while reauthentication is pending; a future pool transport must preserve connection ownership during that phase rather than treating it as a disconnected TCP socket.

Authenticated `SEC_I_CONTEXT_EXPIRED` maps to clean TLS closure. Its original encrypted DATA descriptor can remain unchanged and **must not be copied as plaintext**. The first real close-notify regression failed on precisely that mistaken interpretation and passes after a status-specific fix. Bare transport EOF still fails as truncation; local abort is not a clean peer shutdown. Temporary status-only diagnostics are removed.

## Executed peer and scope

`pearl_schannel_probe` is a non-installed test-only command driver with bounded raw byte queues. The native TLS steps never wait on its stdin/stdout; command IO is outside those steps. A separate Python/OpenSSL `ssl.MemoryBIO` peer supplies real TLS records without any socket or DNS lookup. Python is a development test dependency, **not a miner runtime or GUI**.

The material generator executes only when explicitly requested, creates a fresh synthetic CA/leaf/CRL/key, and returns its key only to the capturing test process. The private driver never logs that JSON, writes a temporary synthetic server key only under explicitly supplied private scratch, loads it into the test server, immediately unlinks the key file and cleans its own temporary directory. It does not read user certificates/configuration or install trust. This differs deliberately from the P-12c public-DER-only generator, which still emits no private key.

The 18 native scenarios cover absent/stale/revoked trust, certificate expiry/future/usage, wrong/missing SAN despite a matching common name, wrong anchor/reference, mandatory client authentication without identity disclosure, pre-handshake expiry, TLS 1.2 fragmented handshake/output, TLS 1.3 actual post-handshake control/revalidation, exact multi-record application bytes, encrypted backpressure, control-phase expiry, cancellation and authenticated-versus-truncated closure. The client-auth fixture follows the real server's missing-certificate alert when Schannel continues without a certificate; it does not manufacture failure by calling the wrong API after local handshake completion. TLS 1.3 control turns and TLS 1.2 absence of those turns are observed separately.

The optional `CANARY_SCHANNEL_MEMORY_TESTS` registration requires both development capabilities, explicit private scratch and an explicitly supplied material-generator interpreter/path (an already installed WSL Python is supported). It downloads/installs nothing and never runs by default. Final platform evidence is recorded in the execution ledger. Schannel/Crypt32 and external OpenSSL internals are not sanitizer-instrumented. Normal automatic-root positives, IP identity, received intermediate-chain admission, explicit key-update/post-handshake-client-auth variants, session-cache policy changes, full native blocking/egress/process isolation, real sockets/endpoints, actual Stratum on Windows and production qualification remain open.

Final evidence: Windows/MSVC default-off full serial **187/187 CTest**, followed by a final rebuild and focused **5/5** after the test-header/platform-refusal additions. The separate capability build passes the selected **3/3** native CTest cases, including **18** Schannel/MemoryBIO scenarios; **five additional complete 18-scenario repetitions** pass with fresh ephemeral material. This selection is not the entire capability-enabled test tree. TLS 1.3 positive runs observe **six** post-handshake control turns, while the TLS 1.2 fragmented run observes **zero**; that does not establish all key-update or post-handshake client-authentication variants.

The split shared-owner/OpenSSL sources rebuild and pass Linux strict-GCC ordinary and own-code **ASan+UBSan with leak detection**, each **6436** checks in the final runs. Fragment-loop counts can vary with ephemeral ECDSA material. Windows/Linux default-off stream fixtures pass **15** checks. Default-off Windows artifact inspection confirms all four TLS/test options OFF, no native TLS references in the library, no Secur32/Crypt32/OpenSSL imports in the disabled executable, and no pool-TLS activation in the ordinary worker artifact. The rebuilt Linux disabled executable has no undefined SSL/X509/BIO/PEM symbols.

The peer reports separately installed Python SSL **OpenSSL 3.5.7**; the explicit WSL generator uses existing `cryptography` **46.0.5**, with no package installation. A separate import probe patches key generation to fail and confirms importing the generator produces neither output nor keys. Architecture/import, staged/source/history privacy and whitespace checks pass. The actual close-notify regression and mandatory-client-auth fixture correction are retained in the scope above. None of these checks qualifies normal automatic Windows trust, external native libraries, native blocking/egress/isolation, actual sockets/pools, physical GPUs/games or production deployment; no installed miner, driver, certificate store or OS policy was modified.
