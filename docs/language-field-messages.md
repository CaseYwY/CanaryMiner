# Language-panel field and review labels (P-13q)

M-I18N/M-UI; R-I18N-001/002; T-I18N/T-UI/T-CONFIG/T-PRIVACY; D-115.

**English source extraction and independent draft rendering, not effective native language.** Eleven stable
`language.field.*`, `language.value.invalid_label` and `language.review.*` keys across sixteen packs (176 texts) cover the
eight ordered field labels, invalid-label recovery and the two honest source/draft review descriptions. Native Language
settings binds English-only helpers, preserving complete frames, field order and navigation/save/discard behavior. Its
shell, review-row envelopes, limitation notices and machine policy values remain separate work.

Display labels never become preference names or machine values. Language ID, formatting locale, digits, order, direction,
ambiguous/emoji cell widths and grouping remain independently stored/validated requests; literal policy values such as
`locale_default`, `ascii`, `logical`, `visual`, `auto`, `ltr` and `rtl` are not renamed. No JSON schema, CLI override,
serialization, current-parent frozen request, effective-language/format status, worker, donation or stop behavior changes.
The grouping on/off values and all parser/validation messages also remain outside this eleven-key scope.

The review labels retain both limitations: English source is **not externally certified** and non-English requests remain
**machine-assisted draft, not human reviewed**. These labels are descriptions, not a review-status authority. For example,
a non-English translation of the English-source description still has machine-assisted requested/rendered metadata; it
does not certify itself or promote another pack. All non-English catalog entries remain drafts, and ordinary effective
presentation remains English/legacy formatting.

The dedicated typed request has no argument container: these are literal-only labels, not an arbitrary template/domain
injection route. Wrappers reuse checked fixed-domain layout, provenance/tone, whole-English ASCII/disabled recovery,
unknown-language review metadata and transactional failure/row policies. They do not load preference files, discover a
locale, activate requests or qualify terminal fonts, shaping or accessibility. Ordinary Language/root/supervisor/core
sources remain guarded against calling any typed renderer.

Fixtures check all 176 texts, exact stable key/field order/placeholder/review/direction parity, English source bytes,
order/direction/width/paint and wrapped rows, unknown language and invalid language/key/tone/policy transactions. A private
fixed-predecessor harness compares **184320 complete native Language frames** across all sixteen requested languages,
eight fields, three pages, widths/heights/colors, changed/unchanged requests and idle/running/CLI-override contexts. It also
compares **34560 synthetic key transitions**, resulting frames and serialized active/draft machine requests with empty
save access. These do not qualify all formatting-locale/policy combinations, real concurrent writers or physical terminals;
actual store/CLI/PTY regressions remain independent. Exact platform/privacy/sanitizer evidence is in the
[execution ledger](architecture/execution-plan.md).

Remaining Language shell/review envelopes/notices, other subpanels/dashboard/raw domains, effective typed native/data-owner/
deployment integration, human review and physical terminal/font/shaping/accessibility gates stay open. No real GPU/game/
pool/power/financial/release qualification or production-miner replacement is implied.
