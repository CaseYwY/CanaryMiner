M-CONFIG/M-UI/M-SUPERVISOR/M-PRIVACY; R-UI-003/007, R-SAFE-001/002, R-PRIV-001/002; T-CONFIG/T-UI/T-INTENT/T-PRIVACY; D-179.

The actual CLI no longer opens language/runtime/game/pool preference stores on its foreground startup path. A finite read-only `inspectPreRunPreferences` invocation uses the existing fixed-target [preference owner](preferences-owner.md) and actual-module sibling helper. It adds no protocol kind, executable search, synchronous fallback, automatic retry, preference write or mining/source capability.

## Modes, receipts and refusal

- Ordinary parent: inspect Language, Runtime, Game and Pool in that order, one exact outstanding Load ticket at a time. The existing CLI override/effective/frozen-default calculation and unqualified game/TLS startup refusals remain in the actual main entry. These sequential original observations are not a transaction across four files.
- Idle CLI: verify terminal admission, then inspect Language before the separate [idle UI owner](idle-preferences.md) becomes editable. Direct embedded panel callers retain their explicitly supplied contexts; this is not a new implicit global language activation.
- Pool-only parent: inspect only the secure-intent declaration for the existing nonordinary pooled-parent guard. Unrequested domain defaults are not validated facts or runtime authority.

A matching Loaded document must pass the existing canonical typed admission. Only a definite helper-side rejected Language read retains the legacy English/CLI-request fallback; originals remain untouched. Missing helper, broken transport or other required read failures refuse startup instead of manufacturing defaults. Raw helper errors, target paths and private originals never become new diagnostics. Configured game policies and TLS requests still cannot activate unqualified native bindings or downgrade to TCP.

## Stop and original ownership

Signal handlers precede these preference reads. Interactive pending inspection accepts Q/Ctrl+C/Esc; redirected ordinary invocation performs no terminal-key polling. Stop revokes the inspection intent/owner before the optional join and cannot issue the next Load or reach device setup in the controlled regression. Idle rejection stays exit 2; explicit inspection stop returns 0; unavailable preferences return the existing configuration failure code.

The result publishes only after all requested reads and settlement succeed under the original native epoch. The actual caller carries that epoch through a native scope into the idle command or later run setup and checks it before device admission. Clearing a transient global fault cannot renew the old observation. This is cooperative software ownership, not a hard OS/console/reaping deadline or native exit proof.
